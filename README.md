# Minecraft EC2 Infrastructure with CDK

This repository provides a production-ready AWS CDK infrastructure for deploying Minecraft servers on EC2 with Docker, CurseForge modpack support, persistent EBS storage, and a Fleet Manager API for server management.

## Features

- **EC2-based Minecraft servers** using Docker (`itzg/minecraft-server`)
- **CurseForge AUTO support** with environment variables for modpack deployment
- **Persistent EBS volumes** with optional DLM backup policies
- **Fleet Manager API** (API Gateway + Lambda) for managing servers:
  - Start/stop servers
  - Check server health
  - Get server metadata
  - Create EBS snapshots for backups
- **Four pre-configured modpack patterns**:
  - Cisco's Adventure RPG Ultimate
  - Better MC [FORGE] BMC4
  - Homestead – Cozy
  - Dungeons & Colonies RPG
- **CDK Pipelines** for CI/CD (Dev → Manual Approval → Prod)
- **Projen** for project automation
- **cdk-nag** compliance checks

## Prerequisites

- Node.js 18 or later
- AWS CLI configured with appropriate credentials
- AWS CDK v2 installed (`npm install -g aws-cdk`)
- AWS account(s) bootstrapped for CDK

## Setup

### 1. Bootstrap AWS Accounts

For each account and region where you plan to deploy:

```bash
cdk bootstrap aws://ACCOUNT-ID/REGION
```

### 2. Create SSM Parameter for CurseForge API Key

Create a plaintext SSM parameter with your CurseForge API key:

```bash
aws ssm put-parameter \
  --name "/minecraft/curseforge/apiKey" \
  --type "String" \
  --value "YOUR_CURSEFORGE_API_KEY" \
  --description "CurseForge API key for Minecraft modpacks"
```

**Note**: The parameter is stored as plaintext (no KMS encryption) as specified in the requirements.

To get a CurseForge API key, visit: https://console.curseforge.com/

### 3. Install Dependencies

```bash
npm install
```

### 4. Generate Project Files

```bash
npx projen
```

### 5. Build the Project

```bash
npm run build
```

## Deployment

### Option 1: Deploy via Pipeline (Recommended)

1. Update account IDs in `src/stacks/PipelineStack.ts`:
   - Replace `111111111111` with your Dev account ID
   - Replace `222222222222` with your Prod account ID

2. Deploy the pipeline:

```bash
npx cdk deploy MinecraftPipeline
```

3. Push your code to the CodeCommit repository created by the pipeline
4. The pipeline will automatically build and deploy to Dev, then wait for manual approval before deploying to Prod

### Option 2: Deploy Directly (For Testing)

Uncomment the direct stack deployment in `src/main.ts` and run:

```bash
npx projen mc:deploy
```

Or:

```bash
npx cdk deploy MinecraftStack
```

## Fleet Manager API Usage

After deployment, the stack outputs include:
- `FleetApiBase`: The API Gateway endpoint URL
- `FleetApiToken`: Authentication token (include as `x-token` header)

### API Endpoints

All requests require the `x-token` header with the authentication token.

#### List all servers

```bash
curl -H "x-token: YOUR_TOKEN" \
  https://API_ID.execute-api.REGION.amazonaws.com/servers
```

#### Get server metadata

```bash
curl -H "x-token: YOUR_TOKEN" \
  https://API_ID.execute-api.REGION.amazonaws.com/servers/ciscos-adventure-rpg/metadata
```

#### Check server health

```bash
curl -H "x-token: YOUR_TOKEN" \
  https://API_ID.execute-api.REGION.amazonaws.com/servers/ciscos-adventure-rpg/health
```

#### Start a server

```bash
curl -X POST -H "x-token: YOUR_TOKEN" \
  https://API_ID.execute-api.REGION.amazonaws.com/servers/ciscos-adventure-rpg/start
```

#### Stop a server

```bash
curl -X POST -H "x-token: YOUR_TOKEN" \
  https://API_ID.execute-api.REGION.amazonaws.com/servers/ciscos-adventure-rpg/stop
```

#### Create backup (EBS snapshot)

```bash
curl -X POST -H "x-token: YOUR_TOKEN" \
  https://API_ID.execute-api.REGION.amazonaws.com/servers/ciscos-adventure-rpg/backup
```

## Architecture

### Server Configuration

Each server includes:
- EC2 instance (default: t4g.small ARM64)
- Amazon Linux 2023 OS
- Docker with `itzg/minecraft-server` image
- Elastic IP for stable addressing
- Persistent EBS volume mounted at `/minecraft`
- Security group allowing TCP/25565 from configured CIDR
- SSM Session Manager for secure access
- CurseForge modpack auto-download support

### Modpack Defaults

| Modpack | Volume Size | Memory |
|---------|------------|--------|
| Cisco's Adventure RPG Ultimate | 60 GiB | 8G |
| Better MC [FORGE] BMC4 | 60 GiB | 8G |
| Homestead – Cozy | 50 GiB | 6G |
| Dungeons & Colonies RPG | 50 GiB | 6G |

### Backup Strategy

Optional DLM (Data Lifecycle Manager) policy:
- Schedules daily snapshots at 03:00 UTC
- Retains 7 snapshots by default
- Tags volumes with `MinecraftData=true`

Additional on-demand backups available via Fleet Manager API.

## Security Notes

- **CurseForge API Key**: Stored as plaintext in SSM Parameter (no KMS encryption as per requirements)
- **Ingress**: Restrict security group rules to trusted IP ranges
- **API Token**: Randomly generated; store securely
- **IAM Roles**: Follow least-privilege principle
- **Route53**: Consider adding A-records for Elastic IPs

## Troubleshooting

### Server won't start

1. Check SSM Parameter exists and is readable
2. Verify CurseForge API key is valid
3. Check EC2 instance logs via Systems Manager Session Manager

### Connection refused

1. Verify security group allows your IP on port 25565
2. Check if Minecraft server container is running: `docker ps`
3. View container logs: `docker logs minecraft`

### Volume not mounting

1. SSH/SSM into instance
2. Check if volume is attached: `lsblk`
3. Check mount status: `mount | grep minecraft`
